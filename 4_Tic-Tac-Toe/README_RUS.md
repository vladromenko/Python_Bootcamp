# Проект: Крестики-нолики

Нужно разработать backend-приложение для игры в крестики-нолики на Python.

Проект создается один раз и используется для всех последующих заданий. Код должен быть разделен на слои, чтобы игровая логика, работа с данными, web-интерфейс и настройка зависимостей не смешивались друг с другом.

Структура проекта должна включать слои:

- `web` — работа с HTTP-запросами и ответами;
- `domain` — бизнес-логика игры;
- `datasource` — хранение данных;
- `di` — настройка зависимостей.

Приложение должно поддерживать несколько игр одновременно. Для хода компьютера нужно использовать алгоритм Минимакс.

## Задание 0. Создание проекта

Нужно создать Python-проект для разработки backend-приложения.

Проект должен состоять из файлов с расширением `.py`. Отдельные файлы могут запускаться напрямую через команду `python filename.py` или импортироваться в общий файл запуска, например `main.py`.

Для работы нужно установить интерпретатор Python. Проект можно создавать в любой IDE, например в PyCharm. При создании проекта нужно выбрать интерпретатор Python, путь для сохранения проекта и название проекта.

В результате должен получиться пустой Python-проект, в котором дальше будет реализовано приложение для игры в крестики-нолики.

## Задание 1. Создание структуры проекта

Нужно создать структуру проекта с разделением на слои.

Каждый слой должен быть отдельным модулем.

В проекте должны быть следующие слои:

- `web`;
- `domain`;
- `datasource`;
- `di`.

В слое `web` должны быть пакеты:

- `model`;
- `module`;
- `route`;
- `mapper`.

Этот слой отвечает за взаимодействие с клиентом: принимает HTTP-запросы, преобразует входные данные и возвращает ответы.

В слое `domain` должны быть пакеты:

- `model`;
- `service`.

Этот слой отвечает за бизнес-логику игры: состояние игрового поля, правила игры, проверку ходов, окончание партии и ход компьютера.

В слое `datasource` должны быть пакеты:

- `model`;
- `repository`;
- `mapper`.

Этот слой отвечает за хранение текущих игр и получение данных из хранилища.

В слое `di` должны находиться конфигурации для внедрения зависимостей.

В результате должна получиться структура проекта, в которой заранее разделены web-слой, domain-слой, datasource-слой и слой настройки зависимостей.

## Задание 2. Реализация domain-слоя

Нужно реализовать доменный слой приложения.

В этом слое нужно описать модель игрового поля в виде целочисленной матрицы.

Также нужно описать модель текущей игры. У текущей игры должен быть UUID и игровое поле.

Нужно описать интерфейс сервиса игры.

В интерфейсе сервиса должны быть методы:

- получить следующий ход текущей игры с помощью алгоритма Минимакс;
- проверить корректность игрового поля текущей игры;
- проверить, закончилась ли игра.

Проверка корректности игрового поля должна определять, что пользователь не изменил предыдущие ходы.

Проверка окончания игры должна определять победу, поражение, ничью или продолжение партии.

Модели, интерфейсы и реализации должны находиться в разных файлах.

В результате должен получиться слой `domain`, который содержит основную игровую логику и не зависит от web-слоя или datasource-слоя.

## Задание 3. Реализация datasource-слоя

Нужно реализовать слой хранения данных.

В этом слое нужно создать класс-хранилище для текущих игр.

В качестве хранилища нужно использовать потокобезопасные коллекции, чтобы приложение могло корректно работать с несколькими играми одновременно.

Нужно описать datasource-модели игрового поля и текущей игры.

Нужно реализовать мапперы между `domain` и `datasource`.

Также нужно реализовать репозиторий для работы с хранилищем.

В репозитории должны быть методы:

- сохранить текущую игру;
- получить текущую игру.

После этого нужно создать класс, который реализует интерфейс сервиса из `domain` и принимает репозиторий как зависимость.

Модели, интерфейсы и реализации должны находиться в разных файлах.

В результате должен получиться datasource-слой, который умеет хранить текущие игры, получать их по UUID и передавать данные в domain-слой через мапперы.

## Задание 4. Реализация web-слоя

Нужно реализовать web-слой приложения с использованием Flask.

В этом слое нужно описать web-модели игрового поля и текущей игры.

Нужно реализовать мапперы между `domain` и `web`.

Нужно реализовать контроллер с HTTP-методом:

`POST /game/{UUID текущей игры}`

Клиент отправляет текущую игру с обновленным игровым полем после хода пользователя.

Сервер должен:

1. получить UUID текущей игры из URL;
2. получить обновленное игровое поле из тела запроса;
3. проверить корректность присланной игры;
4. сделать ход компьютера с помощью алгоритма Минимакс;
5. вернуть текущую игру с обновленным игровым полем компьютера.

Если клиент отправил некорректную игру или изменил предыдущие ходы, сервер должен вернуть ошибку с описанием.

Приложение должно поддерживать несколько игр одновременно.

Модели, интерфейсы и реализации должны находиться в разных файлах.

В результате должен получиться Flask-контроллер, через который клиент может отправлять ход пользователя и получать ход компьютера.

## Задание 5. Реализация di-слоя

Нужно реализовать слой настройки зависимостей.

В этом слое нужно создать класс `Container`, в котором описывается граф зависимостей приложения.

`Container` должен содержать:

- класс-хранилище текущих игр как `singleton`;
- репозиторий для работы с хранилищем;
- сервис для работы с репозиторием.

В результате должен получиться слой `di`, который собирает приложение и связывает между собой хранилище, репозиторий, сервис и web-слой.
